<a id="features"></a>
## ✨ Features

### 📄 1. High-Precision OCR & Multimodal Parsing
* **Hybrid Multimodal Ingestion**: Supports direct drag-and-drop PDF documents, scanned medical records, DICOM report snapshots, and high-resolution laboratory images (`.pdf`, `.jpg`, `.png`, `.webp`).
* **Client-Side & Server-Side Dual Extraction**: Employs client-side PDF.js and Tesseract.js OCR engine for instant local text extraction prior to AI streaming.

### 🛡️ 2. Multi-Provider AI Failover Architecture
* **Primary AI Engine**: **Google Gemini 3.6 Flash** (Multimodal Vision + JSON Mode).
* **Secondary Failover**: **Anthropic Claude 3.5 Sonnet** (via OpenRouter API).
* **Tertiary Failover**: **Groq Llama 3.3 70B** (Ultra-low latency inference).
* **Quaternary Smart Fallback**: Deterministic Clinical Regex Parser ensuring 100% uptime even during total internet/API outages.
* **Live Model Tracking**: Every report display explicitly highlights which AI model generated the result in the top UI bar.

### 📊 3. 5-Stage Live Processing Pipeline Visualizer
* **Real-time Progress Tracker**: Displays active progress percentage and step indicators as the document traverses through:
  1. *Extracting Document Text & OCR*
  2. *Preprocessing Clinical Text Data*
  3. *Building Structured Medical Prompt Engine*
  4. *Querying AI Provider (Gemini / Failover Pipeline)*
  5. *Schema Normalization & Traceability Check*

### 🔬 4. Clinical Parameter & Risk Analysis
* **Abnormal Value Highlighting**: Automatic detection and classification of test parameters into `HIGH`, `BORDERLINE`, or `NORMAL` states.
* **Expected Reference Normal States**: Avoids confusing "Reference: Absent" labels by presenting clear, context-aware normal states (e.g., *"Expected: No chest pain during exercise"*).
* **Risk Stratification Engine**: Classifies overall document risk into `LOW`, `MEDIUM`, or `HIGH` with transparent clinical rationale bullets.
* **Missing Data Warnings**: Automatic detection of incomplete lab panels, missing ECG pages, or absent diagnostic history.

### 📚 5. Patient-Centric Layperson Dictionary & Q&A
* **Medical Term Decoder**: Automatically translates medical jargon (e.g., *Dyspnea*, *Cardiomegaly*, *Hypertension*) into simple layperson definitions.
* **Source Traceability & Evidence Mapping**: Every key finding includes verbatim document quotes for full clinical auditability.
* **Interactive Medical Q&A Chatbot**: Instant follow-up chat interface allowing patients to ask clarifying questions about their specific report.

<a id="installation"></a>
## 🚀 Installation & Local Development

### Prerequisites
* **Node.js**: `v18.0.0` or higher
* **npm**: `v9.0.0` or higher

### Step 1: Clone Repository
```bash
git clone https://github.com/your-username/medexplain-ai.git
cd medexplain-ai
```

### Step 2: Install Dependencies
```bash
npm install
```

### Step 3: Configure Environment Variables
Copy `.env.example` to `.env` and supply your API keys:
```bash
cp .env.example .env
```

Edit `.env`:
```env
# Primary AI Provider (Required for Gemini)
GEMINI_API_KEY="YOUR_GEMINI_API_KEY"

# Fallback Providers (Optional)
OPENROUTER_API_KEY="YOUR_OPENROUTER_API_KEY"
GROQ_API_KEY="YOUR_GROQ_API_KEY"
```

### Step 4: Run Development Server
```bash
npm run dev
```
Open your browser and navigate to `http://localhost:3000`.

### Step 5: Build for Production
```bash
npm run build
npm run start
```

<a id="prompt-strategy"></a>
## 🧠 Prompt Strategy & Responsible Medical AI

To ensure patient safety and eliminate AI hallucinations, MedExplain AI enforces strict prompt engineering rules inside `src/services/promptBuilder.ts`:

1. **Non-Diagnostic Constraint**: The model is forbidden from stating definitive diagnoses. It must use guarded phrasing (*"may warrant evaluation by a healthcare professional"*).
2. **Qualitative Normal States**: The prompt instructs models to never output `"Reference: Absent"` or `"None"` for symptoms, replacing them with clear expected normal states (e.g., *"Expected: Normal sinus rhythm without palpitations"*).
3. **Structured JSON Output Schema**: Forces standard JSON object returns with explicit keys for `confidence`, `riskLevel`, `abnormalResults`, `medicalTerms`, `missingSections`, and `sourceTraceability`.
4. **Source Quote Verbatim Rule**: Extracted findings must include an `evidenceQuote` containing verbatim text from the original report for clinical auditability.

<a id="confidence"></a>
## 📊 Confidence Scores

The confidence score (0–100%) represents a composite validation metric based on:
* **OCR Text Density**: Ratio of recognized character blocks vs noisy pixels.
* **Schema Completeness**: Presence of essential clinical fields (Patient ID, Date, Referral Physician, Findings).
* **Provider Self-Reported Certainty**: Model-specific probability score for key extraction claims.

```
Confidence Tier:
  🟢 90% - 100% : High Accuracy (Clear printed report with complete header and lab ranges)
  🟡 75% - 89%  : Moderate Accuracy (Handwritten notes or slightly distorted scan)
  🔴 < 75%      : Low Accuracy (Incomplete report fragment; warnings automatically issued)
```

<a id="api"></a>
## 🌐 API Documentation

### 1. Document Analysis Endpoint
* **URL**: `/api/analyze`
* **Method**: `POST`
* **Content-Type**: `application/json`
* **Body**:
  ```json
  {
    "filename": "Lab_Report.pdf",
    "fileText": "Extracted report text...",
    "imageBase64": "data:image/png;base64,...",
    "mimeType": "image/png"
  }
  ```
* **Response**: `200 OK` with `StandardMedicalReport` JSON object.

### 2. Medical Q&A Chat Endpoint
* **URL**: `/api/chat`
* **Method**: `POST`
* **Content-Type**: `application/json`
* **Body**:
  ```json
  {
    "question": "What does exertional dyspnea mean?",
    "reportContext": { ... }
  }
  ```
* **Response**: `200 OK` with `{ "answer": "..." }`.
